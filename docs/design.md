# 本地预览环境编排器 — 设计说明

本组件把**声明式的环境描述**收敛为**可运行的预览环境实例**。隔离沙箱由
本地进程（无副作用的 `sleep` 常驻进程）与文件系统（PID 文件 + JSON 快照）模拟，
因此编排、回收、对账、竞争等行为都是真实可观察、可在本地稳定复现的。

## 1. 包结构

| 包 | 职责 |
|----|------|
| `internal/domain` | 声明式模型、运行时状态、可区分错误类型 |
| `internal/graph` | 依赖图校验、拓扑排序、环检测（报告具体环路径） |
| `internal/resources` | 独占端口池、环境数配额（可配置上限，拒绝/排队策略） |
| `internal/secret` | 仅按引用访问的版本化密钥存储（轮换、吊销） |
| `internal/sandbox` | 本地进程生命周期、PID 文件、存活探测、孤儿清理 |
| `internal/store` | 环境快照的原子 JSON 持久化（临时文件 + rename）、基于 flock 的环境文件锁 |
| `internal/engine` | 调谐主循环：Apply/Get/Delete/Reconcile/ReconcileAll、并发控制、回滚、崩溃恢复 |

## 2. 环境模型

- `EnvironmentSpec`：环境名、服务列表、可选 `TTL`。
- `ServiceSpec`：服务名、镜像、`DependsOn`、端口（固定或动态）、密钥引用、环境变量。
- `Environment`（实例快照）：相位、`SpecHash`、`Generation`、每个服务的
  `ServiceStatus`（相位/PID/端口绑定/**密钥版本绑定**/原因）、`ExpiresAt`、`QuotaHeld`。

环境相位：`Pending / Creating / Ready / Degraded / Deleting / Failed / Terminated`。
服务相位：`Pending / Starting / Ready / Blocked / Failed / Stopped`。

`SpecHash` 对声明做**规范化哈希**（切片顺序无关），保证“同一描述重复提交得到同一实例”。

## 3. 调谐规则（Apply）

1. **静态校验**：空名、重名服务、缺镜像、未知依赖、端口名重复、越界端口、
   非法密钥引用等 -> `ValidationError`（原因列表化）；依赖图成环 -> `CycleError`
   （错误中附带环路径）。二者在任何资源分配之前被拒绝。
2. **密钥预解析**：所有引用必须解析成功才允许继续；缺失/版本失效 -> `SecretError`，
   **绝不退化为默认值**，密钥值不进入快照或日志。
3. **创建去重**：同一环境名的并发创建只有一个“领队”申请名额并执行，
   “跟随者”等待并复用领队结果，避免 N 个并发请求抢占 N 个名额。
4. **环境锁串行化**：同一环境的 Apply/Delete/Reconcile 经每环境互斥锁串行；
   不同环境并行。`Get/List` **不获取环境锁**（快照存储自带同步并经 `Clone` 深拷贝
   隔离），因此排队/销毁期间访问方立即得到确定答复，不会被饿死。
5. **按拓扑顺序启动**：所有上游 `Ready` 后才启动下游；同层按名称排序，结果确定。
6. **依赖失败传播**：上游 `Failed/Blocked` 时，下游标记为 **`Blocked`（写明阻塞原因）**，
   不被静默跳过；不相关的依赖分支继续启动；环境收敛为 **`Degraded`**（而非整体回滚）。
7. **更新即收敛（受控重建）**：声明变化时先逆拓扑停止旧服务、释放旧端口，
   再按新描述启动；移除的服务进程与端口被回收，**不累积副作用**；`Generation` 递增。
8. **失败回滚**：基础设施级失败（创建路径上的持久化失败等）回滚已分配的进程、
   端口、名额；回滚器每一步幂等，错误聚合为 `RollbackError`，与原始错误可区分且可重试。

## 4. 资源与配额

- **端口**：`PortPool` 在可配置区间 `[PortMin, PortMax]` 内分配独占端口。
  - 固定端口（`Fixed>0`）冲突即失败；动态端口从低端选取，池满返回明确错误。
  - 重复释放/释放池外端口是**错误**（`ErrPortNotAllocated`），使“已释放”可区分，
    支撑“重试不得重复释放”。
  - 已绑定端口是访问契约：对账时簿记仍在则复用；簿记缺失才重登记；
    若端口已被他者占用，报告 `NotConvergeableError`，**绝不静默换端口**。
- **环境数配额**：`MaxEnvironments` 上限。
  - `PolicyReject`：满员立即 `QuotaExceededError`。
  - `PolicyQueue`：FIFO 排队；名额释放时**直接转交给队首**（计数不虚增），
    等待者 `ctx` 取消则放弃排队且不吞名额。
- 名额归属记录在快照 `QuotaHeld`，更新（受控重建）不重复计数；
  只有持有名额的快照在删除时才归还，杜绝超 draw 归还。

## 5. 密钥约束

- 密钥**只能被引用**（名称 + 可选版本）。引用在创建/更新时解析为具体版本并**固化**
  到服务状态（只存版本号，不存值）；值仅经环境变量注入进程，不落盘、不进日志。
- `Version=0` 为浮动引用：绑定时解析为当前版本；轮换后**新环境**用新版本，
  **已存在环境**（含对账重启）继续读到其绑定版本。
- `Version>0` 为固定版本：始终解析该版本；版本被 `DisableVersion` 吊销后，
  对账重启该服务会得到明确的 `NotConvergeableError`，而不是空值/默认值。

## 6. 并发安全与生命周期

- 同一环境的创建/销毁/调谐经环境锁 + 创建门控串行化；不会出现半创建、重复释放。
- 删除流程：先把快照置为 `Deleting` 并原子落盘（此后 `Get` 立即不可见，
  访问方拿不到正在销毁的实例）-> 逆拓扑停进程 -> 释放端口 -> 转交/释放名额
  -> 清沙箱目录 -> 删快照。每一步幂等，中断后可由 `Delete` 或 `ReconcileAll` 继续。
- 对不存在环境的删除返回 `ErrEnvNotFound`；并发重复删除不会二次释放资源。

### 6.1 多引擎实例共享同一状态目录

环境锁、端口池、配额都可以落到状态目录，从而让多个引擎实例（多进程/HA）
指向同一目录时仍然正确协调：

- **环境文件锁**（`flock(2)`）：同一环境的调谐/销毁跨进程互斥；持锁进程崩溃时
  锁由内核自动释放，不留死锁。进程内仍保留一把互斥锁避免同进程 goroutine 竞争。
- **文件端口位图**：分配记录原子落盘（JSON + rename）并以 flock 保护，
  两个实例不会分到同一端口；恢复时以快照端口集合为权威重建。
- **文件配额信号量**：环境数计数落在 flock 保护的计数文件中，名额释放后
  另一实例无需重启即可观察到。

> 未绑定状态目录时（普通 `New`），端口池与配额退化为纯进程内实现，便于单元测试
> 与嵌入式使用；`NewAndRecover` 会绑定文件状态并以快照为权威重建。

## 7. 到期回收（TTL）

- 临时环境带 `ExpiresAt`；`ReconcileAll(now)` 回收已过期环境，走与 `Delete`
  相同的幂等路径。回收失败可安全重试，**不重复释放已回收资源**，
  也不会误删仍在使用（未过期）的环境。

## 8. 对账与崩溃恢复

- `NewAndRecover` 启动时依据快照重建端口池与配额簿记，并探测快照 PID 的存活：
  已被外部杀死的进程标记为 `Pending`、环境置 `Degraded`，等待对账修复。
- `Reconcile`：
  - 进程被外部杀死 -> 用**固化的密钥版本**与**绑定端口**重启，按拓扑顺序恢复；
  - 沙箱中存在快照未记录的进程/PID 文件（孤儿）-> 清理；
  - 绑定密钥版本失效/绑定端口被他者占用/快照缺服务记录 ->
    `NotConvergeableError`，明确报告不可收敛而非静默造数；
  - `Deleting` 快照 -> 继续完成删除。

## 9. 本地验证方法

```bash
# 常规测试
go test ./...

# 竞态检测（需要 cgo；本机已提供 gcc）
CGO_ENABLED=1 go test -race -count=1 ./...

# 端到端演示（创建/幂等/密钥轮换/到期回收）
go run ./cmd/orchestrator
```

测试日志以 `[flow]` 前缀打印**判定依据**与资源流水（端口分配/释放、进程启动/停止、
名额获取/转交、阻塞原因、对账修复、到期回收），密钥值永不出现。
覆盖的关键场景：并发同描述 Apply、并发创建/销毁、重复销毁、依赖失败阻塞、
密钥缺失/轮换/吊销、端口冲突/耗尽、配额拒绝/排队/取消、到期竞争、
回滚失败重试、孤儿进程清理、跨重启簿记恢复与中断删除续作。

## 10. 关键设计取舍

- 用真实本地进程而非内存假对象，使“外部改动/杀进程/崩溃”能被真实探测，
  对账与恢复不是自证；进程选择无副作用的 `sleep`，停止使用 SIGTERM。
- 地址（端口）作为访问契约在对账中保持稳定，宁可明确报告不可收敛也不静默漂移。
- 服务自身故障（启动失败、其端口不可用）降级为 `Degraded` 并传播 `Blocked`；
  仅当无法维护整体簿记一致性时才全量回滚。
