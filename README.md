# preview-env-orchestrator-go

本地预览环境编排与生命周期管理组件。用**本地进程 + 文件系统**模拟隔离沙箱，
把声明式的环境描述（`EnvSpec`）收敛成可运行的预览环境实例，使创建、访问、
变更与回收在异常与并发场景下都有**确定且可解释**的结果。

## 持久化与多实例（v2）

环境状态不再只活在单个引擎进程内存里：全部状态落盘到一份**共享状态目录**
（`Config.StateDir`，默认 `<WorkDir>/state`），引擎重启后自动恢复；同一台机器上
可以同时跑多个引擎实例指向同一个目录，共享同一份状态。

### 落盘内容（只有引用，没有密钥值）

```
state/
├── lock                 # 全局 flock 锁文件（跨进程串行化全部写操作）
├── events.log           # 跨实例共享的资源分配/释放流水（JSON Lines）
├── inst/<id>.json       # 各引擎实例心跳：实例 ID / PID / 进程启动时间戳
└── envs/<name>.json     # 每个环境一条原子记录（tmp+fsync+rename）
```

每条环境记录（`schema_v=1`）包含：

- 环境描述 `EnvSpec`、描述指纹、生命周期状态、`CreatedAt`/`ExpiresAt`；
- 每个服务的指纹、**占用的端口（端口名→端口号）**、进程 **PID 与
  `/proc/<pid>/stat` 启动时间戳**；
- 密钥**绑定引用**：只存 `环境变量名 -> key@version`，**没有密钥值**；
- `tombstoned` 墓碑位：销毁决定先落盘，再执行进程/端口/沙箱清理。

密钥值只在启动服务的瞬间通过进程环境变量传递，**绝不进入**状态文件、
`events.log`、心跳或沙箱产物；流水里永远只有 `key@version -> $ENV` 这样的引用。

### 恢复与接管

- **端口/配额**：端口分配器状态每次进临界区都按环境记录重建，记录里已占用的
  端口直接恢复归属，恢复期间不会被再分配；环境数上限 `MaxEnvs` 同样以落盘
  记录为准，跨实例全局生效（排队或拒绝策略不变）。
- **进程接管**：重启后按 `PID + 启动时间戳` 重新附挂仍在运行的服务并继续观察；
  时间戳不匹配（进程已死或 PID 已被复用）一律视为不存在，绝不附挂错进程。
- **被外部杀掉**：重新附挂时发现进程已死的服务，`Reconcile` 按原端口、原密钥
  绑定重启修复；修不了（绑定的密钥版本被吊销、端口池耗尽等）返回
  `ErrNotConvergent`（密钥原因同时可 `errors.Is(.., ErrSecretRef)`）。
- **创建/销毁到一半**：创建先写 `Starting` 记录，分配/绑定/起进程每步即时落盘，
  恢复时收敛；销毁先持久化墓碑（对 `Get` 不可见、槽位继续占住），再清理，
  清理每步幂等。无论正常退出、被 SIGKILL、还是跨实例操作，销毁与到期回收
  真正生效都只有一次（可由 `events.log` 中 `destroy` 行数核对）。
- **死实例接管**：心跳超时且 PID/启动时间戳确认进程已消失的实例被判死，
  其他存活实例下一次加锁时清掉它的心跳并接管它的全部环境；一个实例建的
  环境，另一个实例能查到、收敛、销毁，不出现孤儿资源。
- **密钥绑定跨轮换稳定**：已绑定 `key@version` 的环境，重启后、密钥轮换后，
  仍然读当初绑定的版本（包括对账重启时）；只有新建环境解析新版本。绑定版本
  被 `secrets.Store.Revoke` 吊销或引用失效时明确失败，不会悄悄拿最新版本顶替。

### 兼容性

- 状态记录带 `schema_v` 字段，当前版本为 `1`。新版本引擎只接受 `schema_v=1`
  的记录；遇到更高版本或损坏记录会跳过并在流水里报告，不会静默改写。
- 旧的 v1（纯内存、无状态目录）用法无需改动：`New` 现在返回
  `(*Orchestrator, error)`；不配置 `StateDir` 时使用默认目录，单进程语义与
  旧版完全一致。

## 环境模型

```
EnvSpec（声明式描述，不可变输入）
 ├── Name / TTL（0 = 不过期）
 └── []ServiceSpec
      ├── Name / Command（本地进程命令）
      ├── DependsOn      上游依赖，决定启动顺序
      ├── Ports          独占端口申请（Preferred=0 表示自动分配）
      ├── Env            明文环境变量
      └── SecretRefs     密钥引用（Key + Version + 注入的 Env 名）
```

- `EnvSpec.Key()` 是描述的内容指纹，作为**幂等键**：同一描述重复 `Apply`
  得到同一个环境实例，不追加任何副作用。
- 每个环境实例有状态机：`Starting → Ready / Blocked / Failed → Destroying → Destroyed`。
- 沙箱 = 独立工作目录 + 独立进程组（`Setpgid`），进程输出写入沙箱内日志文件。

## 调谐规则

1. **幂等创建**：`Apply` 先校验描述，再按名称查找已有环境——
   指纹相同直接返回现有实例；指纹不同进入**更新**流程。
2. **更新收敛**：更新按服务级指纹做 diff——移除的服务被停止并释放端口，
   变化的服务被替换，**未变化的服务原样保留**（端口、进程不动），
   重复提交相同描述零副作用。
3. **依赖编排**：服务按拓扑序启动；上游在就绪观察窗口内退出即判定失败，
   其全部下游被标记为 `Blocked`（不是静默跳过），无依赖的分支照常启动。
   依赖图有环时描述被直接拒绝（`ErrDependencyCycle`）。
4. **失败回滚**：创建过程中的资源类失败（端口耗尽、密钥缺失等）会**逆序回滚**
   已分配的全部资源（停进程、释放端口、删沙箱）；回滚自身失败返回可区分的
   `ErrRollbackFailed`，环境保留为 `Failed` 待 `Reconcile` 重试，不留孤儿资源。
5. **对账（Reconcile）**：
   - 优先重试此前失败的清理（各步骤幂等，不重复释放）；
   - 检测外部漂移（进程被杀、端口被外部释放）并修复（重启进程、重分配端口）；
   - 无法修复时返回 `ErrNotConvergent` 明确报告。
6. **到期回收**：`ReapExpired(now)` 只回收 `ExpiresAt` 已到期的环境，
   不误删未到期环境；回收失败记录 `reap-failed` 流水并保留环境，下次调用重试。

## 资源与密钥约束

- **端口**：`Allocator` 只在 `[PortMin, PortMax]` 内分配。首选端口冲突时按策略
  重分配最小空闲端口；池耗尽返回 `ErrExhausted`（包装为 `ErrCapacity`），
  绝不无界占用。只有持有者能释放端口，释放幂等。
- **配额**：`MaxEnvs`（单机环境数上限，信号量实现）、`MaxService`（单环境服务数）。
  达到上限时按 `Config.Queue` 策略**排队等待**（可被 ctx 取消）或**立即拒绝**
  （`ErrCapacity`）。
- **密钥**：密钥只能被引用（`SecretRef`），创建/更新时解析并**绑定具体版本**：
  - 引用缺失或版本失效 → `ErrSecretRef` 明确失败，不退化为默认值；
  - 轮换后新建环境使用新版本，已存在环境继续读绑定时固定的版本；
  - 密钥值只通过进程环境变量传递，**绝不**出现在落盘数据、流水日志或沙箱产物中
    （落盘与流水都只有 `key@version -> $ENV` 这样的引用）。
- **并发安全**：进程内互斥锁 + 共享状态目录全局 `flock` 双重串行化，
  多个引擎实例共用一份状态时端口、配额全局一致；销毁中的环境对 `Get` 不可见
  （返回 `ErrDestroying`）；并发/跨实例 `Destroy` 只生效一次，重复调用安全返回。

## 错误分类（可区分的原因）

| 错误 | 含义 |
|---|---|
| `ErrInvalidSpec` | 描述非法（空名、空命令、未知依赖……） |
| `ErrDependencyCycle` | 依赖图有环 |
| `ErrConflict` | 与已有环境冲突（保留给扩展策略） |
| `ErrCapacity` | 环境数/服务数/端口达到上限 |
| `ErrSecretRef` | 密钥引用缺失或版本失效 |
| `ErrDestroying` | 环境正在销毁，对访问方不可见 |
| `ErrRollbackFailed` | 回滚/清理失败，可对账重试 |
| `ErrNotConvergent` | 对账无法收敛 |

均可用 `errors.Is` 判定。

## 本地验证

```bash
# 全部测试（需 CGO 以启用竞态检测）
CGO_ENABLED=1 go test ./... -race -count=1 -v
```

测试覆盖：并发调谐（并发 Apply/Destroy/Get/Reconcile）、依赖失败阻塞下游、
密钥缺失/版本失效/轮换绑定/防泄漏、端口冲突重分配与池耗尽、容量拒绝与排队、
到期回收竞争、回收失败重试（不重复释放）、回滚失败对账重试、外部漂移修复、
更新收敛幂等，以及 v2 新增的恢复/多实例场景：

- `TestRestartGracefulRecovery`：引擎正常退出后新引擎恢复——环境可查、
  状态/端口不变、仍在跑的进程按 PID 附挂、已占用端口不会被再分配、可继续销毁；
- `TestRestartExternalKillReconcile`：重启后发现服务进程被外部杀掉，
  端口不外流，`Reconcile` 修复后服务恢复且端口不变；
- `TestCrashKillRecovery`：用真实子进程 `SIGKILL` 掉引擎，心跳超时后
  新实例接管仍在跑的服务，收敛、销毁均只生效一次；
- `TestRestartSecretRotationKeepsBinding`：重启后再轮换密钥，旧环境仍绑定
  旧版本（含对账重启），新环境用新版本；吊销旧版本后对账明确
  `ErrNotConvergent` + `ErrSecretRef`，不拿最新版本顶替；
- `TestStateFilesContainNoSecretValues`：扫描整个状态目录（记录/流水/心跳/
  锁文件），密钥明文不出现；
- `TestMultiInstanceConcurrency`：两个实例并发创建，端口全局唯一、
  `MaxEnvs` 跨实例生效、跨实例 Get/Destroy 可用、共享流水中销毁只有一行；
- `TestMultiInstanceTakeover`：一个实例退出后，另一个实例接管其环境并完成清理。

全部本地可复现：只用本地进程、文件系统与 `/proc`（Linux），不依赖任何外部
服务或真实凭据；强杀场景由测试自行 `go test -c` 编译辅助子进程完成。
测试日志通过 `Ledger`（内存）打印判定依据与每一次资源分配/释放流水，
跨实例/跨重启的判定依据在共享文件 `state/events.log`，例如：

```
---- 资源分配/释放流水 ----
[alloc-port] env=sec svc=web http=31000
[bind-secret] env=sec svc=web ghost@0 -> $TOKEN   # 只有引用，没有值
[release-port] env=sec svc=web http=31000 (rollback)
```
